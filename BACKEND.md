Backend проекта — репозиторий `Gakko-Mobile/gakko-mobile-backend` (Spring Boot, Kafka, Avro). Он нужен только как справочник: что реально существует на сервере. Модель занятий с отдельными датами (`class_slots`) и операциями администратора есть только в ветке `schedule-administraion`, в `main` её ещё нет. Прототип рассчитан на эту ветку.


Эти сведения отражают предыдущий аудит на 26.11.2026, а не новое чтение репозитория. Backend только для чтения. Никаких изменений файлов backend, коммитов, push или PR. При отсутствии доступа явно укажи это. Локальные симуляции не выдавай за реальные операции. Правила работы: [AGENTS.md](AGENTS.md).

## Дополнительные результаты аудита

- Backend сообщений в main: `/api/v1/messages` — треды DIRECT/GROUP/OFFICIAL, чтение/отправка до 4000 символов, срочность, read receipt; вложений/редактирования/удаления в проверенном контроллере не было. В schedule-ветке модуля не было. Предложено обновить устаревший none «Brak tabel i API wiadomości» на part, не меняя поведение Wiadomości. Решения не зафиксировано.
- Две миграции Flyway V11 (`V11__message_module`, `V11__split_class_slots`): конфликт при merge, команда backend должна перенумеровать.
- Из последнего аудита: статусы Zablokowane/Nieaktywowane в Użytkownicy — предположение прототипа, серверный UserEntity не имел статуса блокировки. Не удалять без отдельного продуктового решения. Отдельный admin endpoint подсчёта режимов уведомлений отсутствовал, но сами настройки и токены есть; специальная аналитика охвата пользователем отвергнута.

## Ankiety: skip logic

Backend skip logic действительно есть: `skipRules` (`triggerOptionId`, `jumpToQuestionId`), `SurveyQuestionDefinitionValidator` проверяет существующий следующий вопрос и условие по тексту варианта/числу шкалы; `SkipLogicEvaluator` и `SurveyAnswerValidator` не требуют ответы на перескоченные вопросы, есть интеграционный тест. В прототипе правила обновляются при переименовании и очищаются при удалении/изменении порядка/типа/границ шкалы; только переходы вперёд, без правил для текста. Ограничения: сервер принимает присланные ответы на пропущенные вопросы; при нескольких правилах multiple choice срабатывает первое, порядок в UI не показан; мобильную реализацию предыдущий агент не проверял.


UI-решения и точка остановки: [PROJECT_STATE.md](PROJECT_STATE.md). При получении ответа команды обнови соответствующий вопрос и только затем согласуй нужное изменение прототипа.
